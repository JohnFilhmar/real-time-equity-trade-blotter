The two defects

These are numbered because they are a sequence, not a list. The first fix is what exposed the second: until SIGTERM actually reached the process, the code containing the second bug had never executed.

01

Graceful shutdown was dead code inside Docker

Fixed
Symptom
docker compose stop backend returned in 0s and the logs carried no shutdown line at all, which reads like success.
Cause
PID 1 was npm run start. npm does not forward SIGTERM to its child, so the handler in backend/src/index.ts never ran. Sockets and the Prisma pool were never closed.
Fix
prisma migrate deploy moved into its own one-shot compose service gated by service_completed_successfully, leaving the API container to run node dist/index.js directly as PID 1. 
$ docker compose exec backend sh -c 'cat /proc/1/cmdline'
before:  npm run start
after:   node dist/index.js
02

The handler, once running, exited 1 every time

Fixed
Symptom
SIGTERM received, shutting down appeared, shutdown complete did not, and the container exited 1.
Cause
io.close() also closes the HTTP server it is attached to, so the following http_server.close() answered ERR_SERVER_NOT_RUNNING and the promise rejected into the failure branch.
Fix
That one error code is now treated as the expected path, since the listener being already closed is exactly what was wanted. 
$ docker compose stop backend   # after both fixes, 1s
backend-1  | SIGTERM received, shutting down
backend-1  | shutdown complete
state=exited exit=0

What this run does not establish

  • The frontend container is healthy, but it still serves the create-next-app scaffold. Nothing about the blotter UI has been verified, because it does not exist yet.
  • No browser was driven. The two-tab claim rests on two Socket.IO clients, which is the same transport a tab would use but not the same thing as a Playwright pass.
  • In the 25 second observation window the live feed emitted trade.created and trade.amended but no trade.cancelled. Cancel carries a 10% weight, so its absence across 5 events is expected rather than evidence of a fault, and the cancel path is covered by the end to end and unit suites.
  • Nothing was load tested. Rate limits are in-process and would need a shared store across replicas.
