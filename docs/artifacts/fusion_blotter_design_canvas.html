Fusion Blotter · design canvas

Three visual directions for the trade blotter, drawn to the same information architecture so they can be compared rather than admired. Rows 1 to 3 are the directions, each reading left to right: the desktop single-page application, the same screen with New trade open and an optimistic pending row already in the grid, then the two phone pages. Row 4 is shared by all three. Rows 5 and 6 carry the remaining features from the brief, including every optional extension, drawn in Direction A.

Brand chrome is cyan/teal. Emerald and rose are reserved for P&L semantics, so a gain never reads as a button. Scroll each row sideways. Every board is also a standalone page under fusion_blotter/.

A · DEEP TERMINAL — near-black navy, hairline rules, mono numerics, electric cyan.

For: eight hours of unbroken screen time. Highest row density here, lowest glare, numbers read fastest.

Trade-off: the least distinctive of the three at first glance. It looks like a tool, not a demo.

B · GLASS HUD — frosted panels on a deep blue-green field, luminous edges, cyan-to-teal gradients, left icon rail, docked flow strip.

For: the reviewer's first ten seconds. Strongest sense of live data, most memorable.

Trade-off: blur and glow cost GPU on a 1,000-row virtualised grid, and glass reduces contrast headroom — it needs discipline to stay AA.

C · INSTITUTIONAL LIGHT — white and cool grey, deep blue structure, cyan as the interactive accent, saved-views sidebar.

For: a bright room, a projector, screenshots in the README. Easiest to justify in a code review.

Trade-off: the least futuristic. Gains most of its character back in dark mode, which the same tokens invert into.

SHARED — tokens on the left, anticipation and loading on the right.

The anticipation board is the one to read closely: skeletons sized to the real grid, the three-frame optimistic lifecycle (sending → confirmed → rejected with retry), staleness, connection lifecycle, error surfaces, reveal order, and a motion table where every entry has a prefers-reduced-motion fallback.

Colours are shown in Direction A tokens; the behaviour is identical in B and C.

FEATURE COVERAGE · DESKTOP — the rest of the brief, including every optional extension.

Sign in (bonus: user authentication). Cancel confirmation, which the first three rows only implied, beside the shared validation-rule set (bonus: trade validation rules). Position summary and P&L in one page (two bonuses), reconciling to the blotter's own KPIs. Audit trail as a full page with field-level before and after (bonus: audit trail).

The two remaining bonuses are not screens: virtualised grid is annotated in the blotter footer, and containerisation is a delivery concern.

FEATURE COVERAGE · MOBILE — the five tabs the bottom bar promises, now all drawn.

Sign in, New trade as a full page with the same validation, Positions and P&L, Activity as the audit trail in feed form, and Profile carrying the role and permission model, where a right the user does not hold is hidden rather than shown disabled.
